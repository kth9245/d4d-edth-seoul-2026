## 결정
리드 말: "일단 플레이 삭제버튼이 필요해", 삭제 범위 답 "걍 삭제 버튼 그냥 싹 삭제하면 되잖아", 설계 승인 "ㅇㅇ삭제 ㄲ". 작전 고르기(0042) 뒤 "플레이 삭제 버튼은 어디 있음", 다시 만들기 승인 "ㄱㄱ".

에이전트 해석:
- 0042의 "플레이 삭제 버튼은 이것으로 대체해 접었다"는 에이전트의 잘못된 해석이었다. 삭제 버튼은 따로 필요하다.
- `DELETE /plays/{id}`: gateway 실행 작전(0042)의 플레이 목록에서 그 플레이를 빼고 `POST /plays`처럼 작전 시작 직전(`paused`)으로 되돌린다. 응답은 남은 `Play[]`, 없는 id는 404. 파일에는 쓰지 않아 gateway를 다시 켜면 시나리오 원본 플레이가 돌아온다.
- 작전이 쓰는 플레이(assign·보고 선택지·switches·적·rotation_plays)여도 막지 않는다.
- 편집기 플레이 화면 저장 줄에 "삭제" 버튼. `confirm()` 대신 두 번 누르기(Part1-22 "처음으로"와 같은 방식). 화면의 404는 저장 전 새 플레이라 오류가 아니고 화면에서만 지운다. 지운 뒤 작전 개요로.

## 이유
- 테스트 중 만든 AI 초안·직접 만든 플레이가 목록에 쌓인다.
- happy path(0024): 사용 중 검사는 시연에 나오지 않는 예외라 만들지 않는다.
- 앱 내장 브라우저가 `confirm()`을 자동 취소한다(Part1-22).

## 버린 대안
- 쓰는 중이면 막기(409): 리드가 "싹 삭제"를 골랐다.
- 저장 안 한 새 플레이만 지우기: 저장한 플레이가 gateway 재시작 전까지 남는다.

## 영향
- contracts/API.md 5절 `DELETE /plays/{id}` 한 줄. gateway `Live.delete_play`, app.py. cop-ui `deletePlay` 액션, `PlayWorkflow` 삭제 버튼, `EditorScreen`이 목록·수정·결과에서 빼고 개요로.
- 작전이 쓰는 플레이를 지우면 다음 재생에서 틱 오류로 실행이 멈출 수 있다. gateway를 다시 켜면 돌아온다.
