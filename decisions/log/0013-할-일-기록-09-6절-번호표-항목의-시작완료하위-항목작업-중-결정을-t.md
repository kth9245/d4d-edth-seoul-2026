4. 쓰기 명령은 origin/main 위에 `tasks/` 두 파일만 바꾼 커밋을 저수준 git 명령으로 만들어 즉시 push한다(작업 폴더·브랜치 무관, 거절되면 최신 main으로 다시 검사·재시도).
5. 작업 중 결정: 내 항목 안에서 끝나는 선택은 `task.py decide`, 계약·남의 모듈·정책을 바꾸는 것은 `/decide`.
6. 이름은 각자 `git config user.name <한글 이름>`, 팀 명단 밖 이름은 기록 거부.

## 이유
- 지금은 시작(SPEC `진행중`)이 ship 때만 main에 올라가 실시간 중복 방지에 쓸모가 없고, 완료는 아무 스크립트도 기록하지 않으며, 액션이 아닌 번호표 항목(REST·지도·틱 루프·튜닝·화면)은 적을 곳이 없다.
- 시작 시점에는 실패 테스트가 있어 ship할 수 없으므로, 기록만 따로 올리는 경로가 있어야 실시간이 된다.
- 하위 항목 단위로 start하면 남의 큰 항목을 넘겨받지 않고 도울 수 있다(결정 0008).

## 버린 대안
- B. ship할 때 함께 올림: 시작 기록이 액션 완료(30분+)까지 안 보여 실시간 중복 방지를 못 한다.
- C. 저장소 밖 실시간 판(공유 웹 DB·구글 시트): 세 사람 에이전트의 쓰기 권한·인증을 오늘 밤 맞춰야 하고 기록이 저장소 밖에 생긴다.
- 기록용 별도 브랜치: 결정 0010(원격 브랜치 없이 main만)과 어긋나고 GitHub에서 NOW.md를 바로 보기 어렵다.

- 수정
  - `scripts/new_action.py`: 예정 행을 가져가기 전에 연결된 항목을 start(남이 진행중이면 거부, 오프라인·기록 파일 오류면 경고 뒤 계속, 남의 배정이면 `배정: X — 채팅에 알리세요`, 결정 0019).
