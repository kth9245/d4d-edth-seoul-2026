## 결정

상황판 기체 메뉴 설계 중(결정 0058·0059와 같은 대화) 사람(kth9245)이 '작전 전환' 접힘 칸(전 기체 귀환·고속 보트 추적·전 기체 순찰 버튼 + 기체·Role 고르기 줄) 사진을 보이며: "전 기체 귀환은 알겠는데 순찰은 어떤 기준으로 되는거지. 그리고 고속보트 추격이 저기있는건 너무 제한적이지 않나 공용범위가 있는것에서". AI가 두 버튼이 시나리오 JSON에 손으로 적은 고정 배정(순찰 = d1 북·d2 남·d3·d4 귀환해 교대 대기, usv·ugv 그대로 / 고속 보트 추적 = d2·usv를 추적 Role로)이고 3분 대본이 고속 보트 추적 버튼을 쓴다고 설명하자, 사람의 메모: "아예 버튼 자체를 없애버리고 전 기체 귀환만 왼쪽 상단으로 옮기기". 이어서 화면에서 사라지는 두 버튼을 데이터에서도 지울지 묻자 답: "데이터에서도 지움 (Recommended)".

(AI 해석)
1. 상황판 오른쪽 아래 '작전 전환' 접힘 칸(SwitchPanel)을 없앤다. 기체 하나 전환 줄은 기체 메뉴(결정 0059)가 대신한다.
2. '전 기체 귀환'은 왼쪽 기체 목록 머리줄('아군 n')에 둔다. 상황판은 `Operation.switches`를 그대로 보여 주므로 그 자리에 버튼이 하나 남는다. 누르면 지금처럼 승인 카드를 거친다(결정 0015·0049, 6대 전부를 바꾸는 명령이라 한 번 더 확인).
3. 두 작전 데이터의 `switches`에서 `track_fast`(고속 보트 추적)·`patrol_all`(전 기체 순찰)을 지운다. 야간 작전 JSON은 손으로, 24시간 작전은 생성 스크립트 `scripts/make_coast_routes.py`에서 지우고 다시 만든다.
4. 3분 대본의 고속 보트 추적 장면은 기체 메뉴 지목으로 바꾼다: d2 → fast1 → '고속 보트 추적', usv → fast1 → '고속 보트 추적(해상)'(결정 0049의 `approve: true`). 운용자 조작은 지금(요청 1 + 승인 1)과 같은 2회다. 지목 시각은 지금의 승인 시각(T+24:00)에 맞춰 뒤 장면 시각을 지키는 것을 목표로 한다(구현 때 확인).
5. Role `track_fast`·`track_fast_sea`와 그 안의 타격 허락 카드(결정 0033)는 그대로 둔다. 지우는 것은 버튼(배정 묶음)뿐이다.

## 이유

- 두 버튼은 이 시나리오 한 장면에만 맞춘 고정 배정이라, 작전 전체에 공통으로 쓰는 자리에 두기에 너무 좁다(사람). '전 기체 순찰'은 이름과 달리 6대 중 4대만 바꾸고 2대는 귀환시킨다.
- 화면에서만 숨기면 시연 대본 테스트가 화면에 없는 버튼을 누르는 흐름을 검사하게 되고, 화면 코드에 숨길 버튼 id를 따로 적어야 한다. 데이터에서 지우면 화면과 데이터가 같다.
- 지목으로 바꾸면 새 기체 메뉴가 시연 화면에 직접 나온다.

## 버린 대안

- 버튼은 두고 누가 어디로 가는지 설명만 붙임: '너무 좁다'는 문제가 남음.
- 화면에서만 빼기: 위 이유.
- 공통 버튼을 지도 아래 재생 막대 옆에 둠: 사람이 왼쪽 위를 골랐다.
