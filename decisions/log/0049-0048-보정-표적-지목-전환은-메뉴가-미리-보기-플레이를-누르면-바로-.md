## 결정

결정 0048의 표적 지목(기체 클릭 → 표적 클릭 → 플레이)은 0048에서 "지금 규칙(결정 0015: 미리 보기 뒤 승인)대로 전환 승인 카드를 거친다"로 적었다. AI가 (가) 승인 카드를 거침 / (나) 플레이 버튼을 누르면 바로 적용(메뉴가 미리 보기, 추천)을 묻자 사람(kth9245): "이렇게 ㄱㄱ".

(AI 해석) 추천안 (나)를 고른 것으로 본다.
1. 지목 메뉴의 플레이 버튼에 "지금 플레이 → 새 플레이 · 표적"을 보여 주는 것이 미리 보기이고, 누르는 것이 승인이다. 승인 대기 카드를 따로 만들지 않는다.
2. 계약: `SwitchIn.approve: bool = False`. 참이면 gateway가 Injection을 처음부터 `status: approved`로 만들어 다음 틱에 적용한다. 그래서 한 번 누른 것이 운용자 조작 1회로 센다(`update_metrics`는 틱 입력의 Injection 수를 센다. 요청과 승인 두 번 보내면 2회로 셈).
3. 기록은 그대로 남는다: Injection(id, 기체→플레이, 기체→표적, approved)이 Frame과 지난 기록에 보인다.
4. 작전 전체 전환 버튼과 기체 하나 전환(지목 없이)은 지금처럼 승인 카드를 거친다(결정 0015 그대로). 바뀌는 것은 지도에서 표적을 지목한 전환뿐이다.
5. 타격은 여전히 메뉴에 없다(0048).

## 이유

- 메뉴가 이미 무엇이 바뀌는지(기체·플레이·표적)를 보여 주므로 같은 내용을 승인 카드로 한 번 더 확인하는 것은 조작만 늘린다. 시연의 주장은 "운용자 조작이 적다"이다.
- 요청과 승인을 두 번 보내 한 번 누른 것을 2회로 세면 지표가 실제 조작과 달라진다.

## 버린 대안

- (가) 지목해도 승인 카드를 거침: 조작이 한 번 늘어남.
- 화면이 요청 뒤 곧바로 승인 요청을 이어 보냄(계약 변경 없음): 한 번 누른 것이 운용자 조작 2회로 셈.

## 영향

- contracts: `SwitchIn.approve`(기본값 false, 0048의 `target_by_vehicle`과 같은 커밋), TS 재생성, `API.md` POST /injections.
- gateway(리드): POST /injections가 approve면 approved로 기록.
- cop-ui(리드, Part1-32): 지목 메뉴 버튼이 approve로 요청.
