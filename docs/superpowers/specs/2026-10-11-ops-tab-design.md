# 실작전 탭 설계 (Part1-48)

2026-10-11 KST · 결정 0067 · 관련 0005(연출 금지), 0026(일시정지), 0040(정답은 화면에 내보내지 않음), 0047(탐지 상태), 0064(탭 이름 시뮬레이션) · 담당: 리드(cop-ui)

## 1. 목적과 완료 기준

리드: "지금 편집기랑 시뮬레이션 있고 이걸 가지고 실제 작전도 가능하다 라고 그냥 말만 하려 그러는데 이게 좀 약한거 같아서 실 작전 창을 더 만들어야하지 않을까 싶음", "그냥 시뮬레이션이랑 똑같은 창을 만들면 어떰".

주장: 훈련(시뮬레이션)과 실제 작전이 같은 화면·같은 조작이다. 두 창의 차이는 화면 안에서 보인다. 시뮬레이션 창은 훈련 통제관 화면(시간 조작, 시뮬레이터만 아는 미탐 적과 적 총수가 보임), 실작전 창은 운용자 화면(실제 시간만, 센서가 본 것만).

완료 기준:
- 헤더 탭이 `편집기 · 시뮬레이션 · 실작전` 셋이고 실작전은 `#ops`.
- 실작전 탭에는 지도 아래 재생 막대(`RunBar`: 시계·재생/멈춤·배속·다음 사건·처음부터)가 없다. 재생 속도는 어디에도 보이지 않는다.
- 실작전 탭에 들어가면 실행이 ×1로 흐른다(멈춰 있었어도). 시뮬레이션 탭으로 돌아오면 재생 막대가 다시 보이고 ×1에서 이어진다.
- 실작전 탭에서 한 번도 탐지되지 않은 적(탐지 상태 `never`, "미탐")은 지도 마커·왼쪽 적 목록·머리줄 적 수와 단계 개수·기체 메뉴 포착 목록 어디에도 없다. 놓친 적(`lost`)·RF만 잡힌 적(`rf`)·무력화(`gone`)·지금 보이는 적(`seen`)은 그대로.
- 결정 대기열·기체 메뉴·표적 지목·MAVLink 패널·운용자 조작 대 수동 기준 숫자는 시뮬레이션 탭과 같다.
- 기존 화면 점검(`scripts/qa/live.json` 등)은 그대로 통과하고, 새 점검 `scripts/qa/ops.json`이 통과한다.

범위 밖(결정 0067): 실기체·SITL 연결, 자료 출처 표시, 실작전 전용 실행(엔진 두 개). gateway·contracts·엔진은 바꾸지 않는다.

## 2. 구조

실작전 탭은 시뮬레이션 탭과 같은 실행을 같은 WS(`/ws`) 연결로 받는다. `App`의 `LiveApp`이 두 탭에서 같은 자리에 그려지므로 탭을 바꿔도 연결이 끊기지 않는다.

```
WS Frame ─▶ LiveApp ─┬─ 시뮬레이션(#live): Screen(frame, ops=false)        재생 막대 있음
                     └─ 실작전(#ops):    Screen(sensedFrame(frame), ops=true)  재생 막대 없음
탭이 #ops로 바뀌는 순간: postRun("/run/live?speed=1") 한 번
```

미탐 적은 Frame 입구에서 한 번 거른다. 미탐 적을 쓰는 곳(지도 마커 `frameMarkers`, 적 목록과 단계 `boardView`·`situationCounts`, 카메라 맞춤 `cameraPoints`, 기체 메뉴 `seenTargets`)을 하나씩 고치면 하나를 빠뜨리기 쉽고, 입구에서 거르면 빠뜨릴 곳이 없다.

| UI-103 | sensedFrame | Frame | Frame | `targets`에서 `trackState(t, t_ms, null).k === "never"`인 적만 뺀 새 Frame. 나머지 칸과 다른 탐지 상태(seen·rf·lost·gone)는 그대로, 입력 Frame은 바꾸지 않음 (결정 0067) |

`tab.ts`(UI 탭 해석)는 `Tab`에 `"ops"`를 더하고 `#ops`를 알아본다. 테스트 한 줄 추가.

## 4. 화면 부품 (테스트 생략 가능)

- `App.tsx`: 헤더에 `<a href="#ops">실작전</a>`(시뮬레이션 다음). 편집기가 아니면 `LiveApp`에 `ops={tab === "ops"}`. `LiveApp`은 `ops`가 참으로 바뀔 때 `postRun("/run/live?speed=1")`을 한 번 보내고(실패해도 throw 없음, 기존 함수), `Screen`에 `ops ? sensedFrame(frame) : frame`과 `ops`를 넘긴다.
- `Screen.tsx`: `ops` prop 하나. 참이면 `<RunBar>`를 그리지 않는다. 그 밖은 그대로.

## 5. 화면 점검 `scripts/qa/ops.json`

`live.json`과 같은 형식. 순서:
1. `/run/reset` 200.
2. 적이 나타났지만 아무도 탐지하지 못한 시각으로 `/run/jump?offset_ms=`(시각은 계획 단계에서 `baengnyeong_night.json`으로 정함).
3. `#live`: 미탐 마커(`.mk.target.never`) 1개 이상, 머리줄 `적 N척`의 N이 미탐을 포함.
4. `#ops`: 재생 막대(`.runbar`) 없음, `.status`가 LIVE, 미탐 마커 0개, 머리줄 N이 3의 N보다 미탐 수만큼 작음. 화면 사진.
5. 몇 초 뒤 `#live`로: `.runbar .run-toggle`이 `▶ 재생`이 아님(흐르는 중), 배속 ×1이 선택됨.
