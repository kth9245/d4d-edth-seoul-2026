# 멸공 작전 적 대응 단계별 카드 흐름 설계

날짜: 2026-10-10 · 작성: 황승주 세션 · 대상 작전: 멸공(`demo/scenarios/baengnyeong_24h.json`)
승인: 사용자 10/10 (여러 대 선택은 C안 반복 카드, 흐름·가정 전체)
이전 설계: `docs/superpowers/specs/2026-10-10-24h-enemies-design.md` 5절(한 카드에 모든 선택지)을 이 흐름으로 바꾼다.

## 목표

적을 발견하면 운용자에게 한 번에 질문 하나씩, 정해진 순서로 묻는다. 한 적에 아군 여러 대를 붙일 수 있다
(몇 대인지는 운용자가 정한다). 임무가 끝나거나 불가능해진 기체에는 다음 행동을 묻는다.

## 제약

- 계약(`contracts/`) 변경 없음. 질문 하나 = 기존 `Report` 하나(`choices` 목록), 고르기 = 기존 `/decide`.
- 화면(cop-ui) 변경 없음.
- 멸공에서만 켠다(작전 roles에 `focus_orbit`이 있을 때). 야간 작전 파일 수정 금지, 매 ship 야간 smoke 결과 동일.
- 액션 파일 80줄, TDD, 단계마다 ship.

## 1. 적 한 기에 대한 흐름

| 단계 | 대상 | 선택지 |
|---|---|---|
| ① 발견 기체 행동 | 적을 발견한 기체 | 공격으로 격추 / 추적·관찰 계속 |
| ② 추적할 아군 | 어떤 적도 발견하지 않은 아군 전부(USV·UGV 포함) | 기체 1대씩 / 대기(추적 안 함) / 전체 대기 |
| ②' 추적 기체 행동 | ②에서 고른 기체마다 | 공격으로 격추 / 추적·관찰 계속 |
| ③ 발견 지점 집중 순찰 | 특정 임무 없는 아군(루틴 순찰 포함) | 기체 1대씩 / 대기 |
| ④ 발견 지점 대체 순찰 | ③과 같음 | 기체 1대씩 / 대기 |
| ⑤ 대응 개요 | 선택지 없는 보고 | 예: "e_drone 대응: d1 관찰, usv·d3 추적, d4 집중 순찰" |

- ②·③·④는 기체를 고르면 같은 단계 카드가 다시 뜨고, 이미 고른 기체는 후보에서 빠진다.
  "대기"를 고르면 다음 단계로 간다. 후보가 없으면 그 단계는 건너뛴다.
- ②에서 기체를 고를 때마다 그 기체의 ②' 카드를 띄운다. ②'는 ③보다 먼저 끝난다.
- "전체 대기": 이미 고른 추적 기체의 ②'를 먼저 끝낸 뒤 ⑤로 간다.
- ①에서 격추를 고르면 ⑤로 간다.
- ③ 집중 순찰: 발견 지점 중심 반경 800 m 원(기존 `focus_orbit`).
- ④ 대체 순찰: 발견 기체가 돌던 순찰 경로를 이어받는다(기존 take).
- 격추: 멸공에 이미 있는 야간 작전의 strike Role.
- 이름: "적기 N" 대신 화면의 표적 id(e_drone, e_usv, e_ugv1…).

## 2. 여러 적의 순서

질문 흐름은 한 번에 적 한 기만 진행한다. 나머지는 대기 줄. 순서는 위험도(`score_target`) 높은 순,
같으면 처음 발견 시간 순. 추적 중 새로 나타난 적(e_ugv1·e_ugv2)도 이 줄에 들어간다.

## 3. 임무가 사라진 기체

매 틱 확인해 해당 기체마다 카드를 띄운다. 선택지는 "기지 복귀" / "현재 위치에서 대기"(그 자리 정지:
드론 호버링, USV·UGV 정지).

- 추적 불가: 드론 배터리가 복귀 기준 아래, USV가 쫓는 적이 땅 위, UGV가 쫓는 적이 바다. 사유를 문구에 적는다.
- 적 제거: 그 적을 추적·집중 순찰하던 기체 전부. 문구 예: "d3: e_drone 제거됨, 임무 없음".

## 4. 범위 밖

체크박스 다중 선택(B안, 시간 남으면), 적 기지 도달 효과, 새 적 아이콘.

## 5. 검증

- 단위 테스트: 단계 진행, 반복 시 후보 제외, 대기·전체 대기, 위험도 순서, 추적 불가 3사유, 적 제거 카드.
- 헤드리스 멸공 실행(T+40): e_drone 흐름 → e_usv 흐름 순서로 카드가 뜨는지.
- 야간 smoke 결과 그대로.
