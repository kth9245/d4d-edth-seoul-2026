# T1 공격 작전 "해안 거점 무력화" 설계 (초안)

상태: **설계 초안, 구현 전.** 코드·계약·시나리오는 아직 바꾸지 않았다. 작성: 최동호 (2026-10-10).
읽는 사람: 이 작전을 같이 만들거나 검토하는 팀원. 이 문서만 읽어도 무엇을 왜 만드는지 알 수 있게 썼다.
표시: **[확정]** = 최동호가 정한 것, **[초안]** = 제안이며 아직 임의 값이거나 결정이 필요한 것.

용어: 이 문서는 개념어 **Role**(기체 하나의 행동 흐름)을 쓴다. 결정 0052가 기존 이름 play를 role로 바꾸는 중이라(Part1-36) 코드에는 아직 `play`, `plays`, `play_by_vehicle` 같은 이름이 남아 있을 수 있다.

## 1. 한 문장
무인기(정찰·무장 드론)·무장 수상정·지상 로봇을 한 명의 지상 운용자가 Role로 지휘해서, 가상 해안 적 거점을 **찾고(RF 방출 단서) → 확인하고 → 운용자 승인으로 무력화하고 → 결과를 평가**한다. 위협 판단과 역할 재부여는 T1에서 만든 방식 그대로다.

## 2. 왜 만드는가
지금까지 T1 시나리오는 백령도로 침투하는 보트를 막는 **방어 위주**였다. 같은 체계(Role, 카드, 인간 승인, 하한선 규칙)로 **공격 임무**도 보여 주려는 것이다. 정찰·확인·타격을 여러 종류의 무인체계에 나누는 것이 T1-1의 "1인 다중 무인기 통제"를 더 입체적으로 보여 준다.

이 작전은 T1 계열이다. 유인기와 CCA는 **T3-2 작전**(`docs/superpowers/specs/2026-10-10-t3-2-cca-operation-design.md`)에만 나오고 이 작전에는 없다.

## 3. 정해진 것 [확정]
1. 기존 백령도 방어 작전은 그대로 두고, 공격 작전을 **새 작전으로 따로** 만든다.
2. 아군은 **무인기(드론), 무장 수상정, 지상 로봇**이다. 운용자는 조종사가 아니라 화면 앞 **지상 운용자** 한 명이다.
3. 지도는 **백령도 타일**을 재사용한다. 작전 이름과 가상 좌표로 방어 작전과 구분한다.
4. 적은 **완전히 가상인 고정 거점**이다. 실제 시설·표적·개인과 무관하다.
5. 타격은 **항상 운용자 승인**을 거친다(결정 0033). 자동 표적 지정·교전 판단이 아니다. 무장은 가상 수량이다.
6. 데이터는 모두 가상이다. 실제 기체·무장 제원은 쓰지 않는다.

## 4. 작전 구성 [초안]
작전 id(안): `baengnyeong_strike`. 기체와 능력은 온톨로지(결정 0038)에서 읽은 것이다.

**아군** (기체 종류와 능력은 현재 `baengnyeong_night.json`의 온톨로지 기준)
| 영역 | 기체 | 종류 | 능력 | 이 작전에서의 역할 |
|---|---|---|---|---|
| 공중 | d1·d3·d4 | 정찰 드론 | 이동, 감시, 접근, 중계 | 방출원 탐지(RF)와 확인 |
| 공중 | d2 | 무장 드론 | + **타격** | 타격 |
| 해상 | usv | 무장 수상정 | 이동, 감시, 접근, + **타격** | 해안 접근, 감시, 타격 |
| 지상 | ugv | 지상 로봇 | 이동, 지점 감시(`watch_point`)만 | 지상 관측점. **타격·중계 불가** |

지상 로봇의 타격 불가는 약점이 아니라 시연 요소다. 온톨로지가 "이 기체에 타격 선택지가 없는 이유"를 이미 설명하므로, 능력 추론 경로를 보여 줄 수 있다.

**적과 보호 대상**(모두 가상, 고정)
| 요소 | 방출 | 설명 |
|---|---|---|
| 거점 A | **방출 중** | 첫 단서. RF로 먼저 잡힌다 |
| 거점 B | 무음 | 스캔해야 보인다 |
| 거점 C | 무음 | 지원 거점 |
| 타격 금지 구역 | — | 근처의 가상 민간 시설. 부수피해 검사용 |

**위치 제약**: 안전 규칙상 타격 목표는 작전 구역 안이어야 한다(`outside_zone`). 구역은 위도 37.9~38.0, 경도 124.56~124.84다. 거점과 금지 구역은 이 안의 가상 지점으로 하고, 기존 상륙 예상 지점(37.978, 124.70)과 기체 기지 부근을 피해 구현 때 지도에서 정한다. 이 문서에는 구체 좌표를 적지 않는다.

## 5. Role 대응 [초안]
| 임무 | Role | 상태 |
|---|---|---|
| 해안 정찰 순찰 | `coast_a/b` 계열(해안 순찰) | 재사용 |
| 방출원 확인 | 근접 확인 Role(접근·감시) | 재사용 |
| 지상 관측점 | 지상 로봇의 상륙 지점 대기 Role 변형(`watch_point`) | 수정 |
| 타격 | 타격 Role(`strike_target`), 무장 드론·수상정 | 재사용(대상이 고정 거점) |
| 귀환·교대 | 귀환 Role, 교대·이어받기 | 재사용 |
| 통신 두절 자율 | 두절 때 갈 단계(`link_lost_step`) | **신설**(T3 문서 7절과 공유) |

## 6. 3분 시연 흐름 [초안]
시각은 구현 뒤 측정해서 확정한다. 순서만 정한다.

1. **탐지**: 정찰 드론이 거점 A의 방출(RF)을 먼저 감지한다. 눈으로는 못 본 "방출원 미확인" 단서 단계다. *(재사용: RF 방출 단서, 결정 0039·0040)*
2. **확인**: 운용자가 드론에게 확인 Role을 준다. 스캔되면 종류가 판별되고 위험 점수와 이유가 카드로 올라온다. 지상 로봇이 관측점으로 붙어 정보 신뢰도를 보강한다. *(재사용)*
3. **재임무**: 운용자가 무장 드론과 수상정에 타격 Role을 부여한다. *(재사용)*
4. **대응안 추천**: 승인 카드에 "관찰 유지 / 타격" 대안이 근거와 함께 뜬다. 근거에 **교전 가능성**(거리, 도달 시간, 정보 신뢰도)과 **부수피해 검사**(금지 구역과의 거리)가 보인다. *(신설)*
5. **인간 승인과 타격**: 운용자가 승인하면 가상 타격이 실행된다. 승인이 없으면 차단된다(결정 0033). *(재사용)*
6. **결과 평가**: "성공 / 부분 / 실패"와 신뢰도가 카드로 뜬다. 부분이면 재타격 여부를 운용자가 다시 결정한다. *(신설)*
7. **손실과 이어받기**: 기체 하나가 손실되면 역할 공백이 생기고 예비가 이어받는다. 이 장면은 시뮬레이션 규칙이 아니라 **시나리오 이벤트로 연출**하는 안이다. *(재사용: 역할 공백·교대, 결정 0037)*
8. **통신 두절**: 기체 하나가 방해 지대에서 끊기면 허가된 범위 안에서만 행동한다(타격 금지). *(신설)*
9. 끝에 운용자 행동 수와 판단 시간을 보여 준다. *(일부 신설)*

## 7. 새로 필요한 것과 영향 [초안]
| 요소 | 내용 | 영향 |
|---|---|---|
| 고정 거점 표적 종류 | 표적 종류에 거점 추가(예: `site`). 속도 0과 대기 Role, 방출 시작 시각(`emit_start_offset_ms`)은 이미 있다 | 계약(`TargetKind`), 리드 결정 |
| 결과 평가 | 거점의 필요 타격 횟수. 첫 타격은 "부분", 필요 횟수에 닿으면 무력화. 결과 카드(성공·부분·실패, 신뢰도)와 재타격 선택 | 계약(`Target` 필드, `ReportKind`), sim, runtime |
| 교전 가능성 | 순수 함수 `engagement_feasibility(거리, 도달 시간, 정보 신뢰도)`. 승인 카드 근거로 표시. 정보 신뢰도는 탐지 상태(탐지 중 / 놓침 / RF만 / 미탐, 결정 0047)에서 얻는다(예: 탐지 중 0.9, 놓침 0.5, RF만 0.4, 미탐 0.0은 **임의 값**) | sensing(최동호), 표시는 리드 |
| 부수피해 검사 | 타격 금지 구역(`Operation.no_strike_zones`)과 목표의 거리를 카드에 표시. **참고 정보로만 둘지, 위반 시 차단하는 규칙으로 할지는 결정이 필요하다.** 차단 규칙은 하한선 3개(출처·구역·귀환 배터리)에 규칙을 더하는 **정책 변경**이다. 현재 제안은 참고 정보 | 계약, safety, 정책(리드) |
| 가상 무장 수량 | `VehicleSpec.munitions`와 타격 때 소모, 0이면 타격 선택지 없음 | 계약, runtime |
| 통신 두절 자율 | T3 문서 7절의 한도표 그대로(두절 때 타격 금지) | sim, runtime |

**바뀌지 않는 것**: 위협 점수의 척도(백령도 그대로 쓸 수 있다), 하한선 3개 규칙, 카드와 이어받기, 인간 승인 원칙.

## 8. 작전을 시연에 올리는 방법
- 시나리오 JSON을 `demo/scenarios/`에 두고 `DEMO_SCENARIOS`(`modules/gateway/app.py`)에 한 줄 추가하면 작전 고르기에 올라간다.
- 편집기의 "작전 새로 만들기"(결정 0053)는 빈 작전을 만들지만 **gateway 메모리에만 저장되고 다시 켜면 사라진다.** 시연용은 JSON 파일로 남겨야 한다.

## 9. 평가 지표
기존 `operator_actions` 대 `manual_baseline_actions`, `open_reports_max`, `role_gap_ms`, `mission_success`를 쓴다. **신설 [초안]**: 판단 시간(카드가 뜬 뒤 결정까지, 카드의 `t_ms`와 `resolved_ms`로 계산 가능), 재타격 횟수.

## 10. 단계와 우선순위 [초안]
| 단계 | 내용 | 비고 |
|---|---|---|
| 1 | 고정 거점, 방출 프로필, 점수, 카드(작전 JSON과 거점 종류) | 가장 작음. 계약 변경은 거점 종류 하나 |
| 2 | 교전 가능성과 부수피해 표시 | sensing 순수 함수, 표시는 리드 |
| 3 | 결과 평가와 재타격 | 계약·sim·runtime |
| 4 | 가상 무장 수량 | 선택 |
| 5 | 통신 두절 자율 | T3 작전과 공유. 백령도에도 적용 가능 |

T3는 개념 결과물도 인정되므로 1~3단계와 짧은 시연을 최소 목표로 본다. 동결(일요일 06:00)이 가깝고 시나리오·화면은 다른 분들이 수정 중이라, 시나리오 파일은 담당자와 먼저 맞춘다. 공수는 아직 측정하지 않았다.

## 11. 결정이 필요한 것
1. 표적 종류에 고정 거점을 추가하는 계약 변경 승인(리드).
2. 결과 평가용 필드(`Target`의 손상 상태 등)와 결과 카드 종류.
3. 부수피해 검사를 참고 정보로 둘지, 차단 규칙으로 할지(정책).
4. 가상 무장 수량을 이번 범위에 넣을지.
5. 작전 id와 시나리오 파일 담당(리드·황승주와 협의).

## 12. 한계와 정책
- 모든 수치와 좌표는 가상이고 임의 값이다. 실제 시설, 표적, 무장 제원을 쓰지 않는다.
- 타격은 추상적인 가상 동작이며 **항상 운용자 승인**을 거친다. 자동 표적 지정·교전 판단이 아니다.
- 이 문서는 설계 초안이고 구현되지 않았다. 수치와 시각은 구현 뒤 측정해 고친다.
- 근거: `contracts/API.md`, 결정 0033(타격 승인), 0037(해안 순찰 교대), 0038(온톨로지), 0039~0043(위협도), 0046(카드 하나당 드론 하나), 0047(탐지 상태), 0052(play를 role로), 0053(작전 새로 만들기), T3-2 설계 문서.
