# 멸공 적 대응 단계별 카드 흐름 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 멸공에서 적 발견 시 한 번에 질문 하나씩(①→②→②'→③→④→⑤) 카드를 띄우고, 임무가 사라진 기체에 "기지 복귀 / 현재 위치에서 대기"를 묻는다.

**Architecture:** 흐름 상태를 따로 저장하지 않는다. 매 틱 `raid_next`가 지금까지의 raid 카드(`id`가 `raid-`로 시작)와
결정 목록을 읽어 다음 질문 카드 하나를 만든다(열린 raid 카드가 있으면 만들지 않음). 카드의 선택지는 기존 `Choice.role_by_vehicle`로
기체를 옮기므로 `apply_decision`은 그대로 쓴다. `raid_idle`이 매 틱 임무가 사라진 기체 카드를 만든다.

**Tech Stack:** Python 3.12, pydantic 계약 모델, pytest. 실행은 WSL `~/work/d4d-edth-seoul-2026`, `uv run pytest`.

**Spec:** `docs/superpowers/specs/2026-10-10-24h-raid-flow-design.md`

## Global Constraints

- 계약(`contracts/`)·cop-ui 변경 없음. 카드 kind는 기존 `target_detected`(질문)·`target_neutralized`(⑤ 개요, 알림 전용).
- 멸공에서만: `"focus_orbit" in roles`일 때만 켠다. 야간 작전 파일 수정 금지, 매 ship 야간 smoke 결과 동일
  (`smoke OK: 5052 ticks ... '근접 확인' switched 3 vehicles ... operator_actions=1`).
- 액션 파일 80줄 이하(`tools/check_specs.py`), 새 액션은 `scripts/new_action.py`로 만들고 `modules/runtime/SPEC.md`에 RT 번호.
- 표시 이름은 표적 id 그대로(e_drone…). "적기 N" 문구 금지.
- 테스트는 `-n 2` 이하(WSL 다운 방지).

## Review Focus

1. 같은 틱에 결정과 새 질문이 겹칠 때: 결정 적용(3단계) 뒤에 `raid_next`가 돌아 한 틱에 카드가 둘 열리지 않아야 한다.
2. 흐름 도중 그 적이 무력화되면: 남은 ②~④를 건너뛰고 ⑤로, 붙은 기체는 `raid_idle` 카드를 받아야 한다.
3. 흐름 도중 후보 기체가 다른 카드로 옮겨지면: 다음 반복 카드 후보에서 빠져야 한다(그 틱 상태로 다시 계산).
4. 5.3 단계 `fleet_choices` 재계산이 raid 카드 선택지를 덮어쓰지 않아야 한다.
5. 한 기체에 `raid_idle` 카드가 매 틱 새로 쌓이지 않아야 한다(열린 카드가 있으면 안 만듦).

각 줄의 테스트는 Task 2·3·4에 있다.

### Task 1: raid_cards — 후보와 선택지 만들기

**Files:**
- Create: `modules/runtime/actions/raid_cards.py` (RT-18, `new_action.py`로 생성)
- Test: `modules/runtime/tests/test_raid_cards.py`

**Interfaces:**
- Produces:
  - `STRIKE="strike"`, `HOME="go_home"`, `HOLD="standby"`, `TRACK_ROLE={"air": "watch", "sea": "track_sea", "ground": "track_ground"}` (기체 spec domain → role)
  - `act_choices(v: str, tid: str) -> list[Choice]` → `[Choice(id=f"strike_{v}", label=f"{v} → 공격으로 격추({tid})", role_by_vehicle={v: "strike"}, target_by_vehicle={v: tid}), Choice(id=f"observe_{v}", label=f"{v} → 추적·관찰 계속({tid})")]`
  - `trackers(states, specs, targets, exclude: set[str]) -> list[VehicleState]`: status ready/active, `target_id is None`, `pending_report_id is None`, id 미포함 exclude, 그리고 어떤 표적의 `seen_by`에도 없음.
  - `free(states, op, exclude: set[str]) -> list[VehicleState]`: status ready/active, `target_id is None`, role_id가 `None`·`standby`·`op.rotation_roles` 중 하나, exclude 미포함.
  - `pick_choices(stage: str, cands, tid: str, roles_by: Callable[[VehicleState], str]) -> list[Choice]`: 기체마다 `Choice(id=f"{stage}_{v}", label=..., role_by_vehicle={v: roles_by(s)}, target_by_vehicle={v: tid})` + `Choice(id=f"{stage}_skip", label="대기")`; stage=="track"이면 끝에 `Choice(id="track_allstay", label="전체 대기")`.
    라벨: track `"{v} → {tid} 추적"`, focus `"{v} → {tid} 발견 지점 집중 순찰"`, cover `"{v} → {tid} 발견 지점 대체 순찰"`.
  - `idle_choices(v: str) -> list[Choice]` → `home_{v}`("기지 복귀", role go_home), `hold_{v}`("현재 위치에서 대기", role standby).

### Task 2: raid_next — 단계 진행

**Files:**
- Create: `modules/runtime/actions/raid_flow.py` (RT-19)
- Test: `modules/runtime/tests/test_raid_flow.py`

**Interfaces:**
- Consumes: Task 1 전부.
- Produces: `raid_next(reports: list[Report], decisions: list[Decision], states, targets, op, roles, specs, t_ms: int) -> Report | None`
  - `"focus_orbit" not in roles` → None. 열린 raid 카드(`id.startswith("raid-")`, choices 있음, resolved 아님) → None.
  - 대상 적: `seen_by` 또는 `reported_by`가 있는 표적, `(-threat, first_seen_ms)` 순. ⑤ 개요 카드(`raid-{tid}-done`)가 이미 있는 적은 끝난 것.
  - 한 적의 진행은 그 적의 해결된 raid 카드와 각 카드의 결정 `choice_id`로 계산한다(결정은 `Report.decision_id`로 찾음):
    1. `raid-{tid}-act` 없음 → ① 카드: vehicle_id=발견 기체(`first seen_by`), `act_choices`.
    2. ① 결정이 `strike_*`이면, 또는 적이 무력화됐으면 → ⑤.
    3. ② 반복: 카드 id `raid-{tid}-track-{n}`. 직전 결정이 `track_{v}`이면 먼저 `raid-{tid}-tact-{v}`(②' `act_choices(v)`), 그 다음 `track-{n+1}`.
       `track_skip`이면 ③으로. `track_allstay`이면 아직 안 물은 ②'만 묻고 ⑤로. 후보(`trackers`, exclude=이 흐름에서 고른 기체)가 없으면 ③으로.
    4. ③ `raid-{tid}-focus-{n}`(`free`, role focus_orbit), ④ `raid-{tid}-cover-{n}`(`free`, role=발견 기체의 `role_id` 순찰 Role) 같은 규칙, `_skip`·후보 없음이면 다음 단계.
    5. ⑤ `Report(id=f"raid-{tid}-done", kind="target_neutralized", text=f"{tid} 대응: ...")`, choices 없음. 문구는 이 흐름에서 고른 기체를 단계별로 나열(예: `"e_drone 대응: d1 관찰 · 추적 usv, d3 · 집중 순찰 d4"`).
  - 질문 카드 kind=`target_detected`, target_id=tid, text 예: `"{tid} 발견({발견 기체}) · ② 추적할 아군 선택"`.

  - `test_track_skip_moves_to_focus`, `test_allstay_finishes_tracker_acts_then_summary`
  - `test_higher_threat_enemy_first_then_first_seen` (Review Focus 순서)

### Task 3: raid_idle — 임무가 사라진 기체

**Files:**
- Create: `modules/runtime/actions/raid_idle.py` (RT-20)
- Test: `modules/runtime/tests/test_raid_idle.py`

**Interfaces:**
- Consumes: `idle_choices`, `target_domain`(RT-15).
- Produces: `raid_idle(reports, states, targets, specs, land, roles, t_ms) -> list[Report]`
  - `"focus_orbit" not in roles` → `[]`.
  - 대상: role이 `watch`·`track_sea`·`track_ground`·`focus_orbit`·`strike`이고 `target_id`가 있는 기체. 그 기체에 열린 `raid-idle-{v}-` 카드가 있으면 건너뜀.
  - 사유(첫 번째 맞는 것): 표적 무력화 → `"{tid} 제거됨, 임무 없음"`; USV이고 `target_domain(tg)=="ground"` → `"추적 불가: {tid} 지상 진입, 수상정은 땅에 못 오름"`;
    UGV이고 `"sea"` → `"추적 불가: {tid} 해상 진입, 지상로봇은 바다에 못 들어감"`; 드론이고 `battery_pct`가 `relieve_hover`와 같은 복귀 기준 아래 → `"추적 불가: 배터리 {pct:.0f}%"`.
  - 카드: `Report(id=f"raid-idle-{v}-{t_ms}", kind="target_detected", vehicle_id=v, target_id=tid, text=f"{v}: {사유}", choices=idle_choices(v))`.
